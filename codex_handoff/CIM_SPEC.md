## 1. 目标与边界

构建 RISC-V 控制的数字执行单元，在 FPGA 上用可综合的低比特 CiM 宏代理运行一个完整 INT8 点卷积算子。用户已有数字/FPGA基础，计划每周投入约35小时、2–3个月交付，可使用集创赛竞业达 K7 板。准确 FPGA part、板卡版本和现有 RISC-V 工程接口尚未确认。

首版 K=64、N=64 固定，M 为运行时 1..125。输入/权重/偏置/量化参数都来自运行时存储内容；CPU配置后一次启动，硬件自主完成全任务。输入输出布局固定，支持短任务和长任务连续执行。

不以全网 KWS、真实模拟宏能效或新 CPU 为第一版目标。不新增自定义 ISA、通用编译器、任意尺寸/尾通道、稀疏模式、ADC噪声建模、多宏系统、DDR通用DMA。复用已有总线、存储与 RISC-V 基础。

## 3. 数值合同

### 3.1 输入与权重

输入存储字节按有符号 INT8 q 解释。固定 z_a=-128，权重对称零点0。内部统一使用：
u = q + 128，u 属于[0,255]。

硬件可翻转输入字节 MSB，再按 unsigned 解释。原始正确累加：
C[p,o] = sum_i ((q[p,i]+128)*W[o,i]) + bias[o]
       = sum_i (u[p,i]*W[o,i]) + bias[o]。

本层 bias 不再加 128*sum(W)，避免重复处理零点。第一版的输入/输出零点均固定-128，不增加运行时任意零点模式。

分解：
u = u_L + 16*u_H，其中 u_L/u_H 都是 U4。
w = w_L + 16*w_H，其中 w_L 为 U4，w_H 为 S4。
权重低、高 nibble 放在相邻两个物理列：column[2j]低U4，column[2j+1]高S4。

一次 A4 操作对16个W4列产生16个原生点积；相邻列配对后得到8个 W8×A4 贡献。先处理低输入 nibble，再处理高输入 nibble，形成8个最终输出通道：
r_low[j] = zero_extend(D[2j]) + (sign_extend(D[2j+1]) << 4)
r_high[j] 同理
C[j] = r_low[j] + (r_high[j] << 4) + bias[j]。

bias 在完整重建之后加一次。每个原生结果先扩展到 signed INT32，再移位相加。权重低 nibble 不能按 S4 解释；sign_out 若出现，表示输出类型，不表示该次结果是否为负。

K64原生结果边界：
- U4×U4：0..14400，U14，零扩展。
- U4×S4：-7680..6720，S14，符号扩展。

此前对固定真实权重/bias的静态计算：
C跨全部通道和全部合法U8输入的范围为[-551440,503000]。
四个加权部分和的保守绝对值和不超过2333760，加当前bias仍在INT32内。
这些是可复算的分析结果。更换权重/bias时，参数准备工具用宽整数检查每个通道的累加范围，不让溢出静默回绕。

### 3.2 逐通道量化

锁定 TensorFlow v2.16.1 reference integer Conv 和 TFLITE_SINGLE_ROUNDING=0 的双舍入语义，使用 INT32 accumulator overload。
流程：
INT32点积重建 -> bias -> MultiplyByQuantizedMultiplier(int32,multiplier,shift)
-> output_offset(-128) -> clamp[-128,127] -> INT8。

当前输出zero-point=-128，clamp下限-128同时满足fused ReLU下限。

必须按固定参考实现处理 signed high multiply、负数舍入、RoundingDivideByPOT 和饱和。宽乘积至少64bit；输出offset加法保留足够宽度后再裁剪，不能提前压成INT8。不要用普通浮点round或随意算术右移替代该合同；也不要因为内部乘积宽就改调参考实现的int64 accumulator overload。

参数准备按 input_scale*weight_scale[o]/output_scale 生成有效scale，使用同版本 QuantizeMultiplier 语义。应从input/weight/output scale转double后计算；不能直接假设已经舍入的bias_scale/output_scale逐位等价。硬件接收整数参数，无浮点硬件。

当前有效scale约[0.002702844686064139,0.006526506741479271]，shift仅-8或-7。
第一版只需支持非正shift的合法范围并在接口中明确；对超出所支持范围的配置由参数准备/驱动拒绝，不能悄悄夹成另一个数。当前模型覆盖的模式必须完整支持。bias加法和输出offset的参考比较使用不会溢出的合法参数。

Golden使用直接宽整数MAC，再调用/严格对照已锁定的官方量化函数。最小独立C++封装或与该封装校验过的Python实现均可；不要求构建整个TensorFlow仓库。RTL分片算法不能作为唯一Golden。

## 4. 字节布局与本地数据端口

全部小端。各基址至少4B对齐；第一版输入、权重、参数和输出区域互不重叠。
索引：p=0..M-1；i=0..63；t=0..7；j=0..7；o=8t+j。

- 输入INT8：A_BASE + 64*p + i。
- 输出INT8：Y_BASE + 64*p + 8*t + j。
- 预打包权重字节：W_BASE + 512*t + 8*i + j，内容是W[8*t+j,i]的原始INT8位表示。
- 每个权重tile为512B，64行；每行8个权重字节，组成64bit宏权重写入数据。
- 参数按通道结构排列：P_BASE + 12*o + 0为bias(INT32)，+4为multiplier(INT32)，+8为shift(INT32)。

权重打包可在主机/软件准备阶段完成一次，提供工具和逆向对应说明。CPU不参与每次低位运算、部分和重建或每个向量的循环调度。

加速器本地端口默认32bit共享读写，每周期最多接受一次32bit请求，不设隐含无限带宽：
- 请求具备valid/ready、字节地址、读写标志、写数据和byte-enable。
- 读响应具备有效标志与32bit数据，需按实际请求返回一次。首版允许最多一个未返回读请求，允许旧响应消费与下一读请求同拍，以便达到流水化服务率。
- 若读响应不带ready，发出请求前就保证落点。响应到达后不能丢弃。
- 本地SRAM写入以请求被接受且存储提交为完成；真实总线适配若存在后续写响应/可见性要求，要延伸到真正提交点。
- valid而ready为0期间，请求地址、数据和控制保持稳定。
- 两次32bit读取组装一行64bit宏权重；共享口带宽统计计入权重与输出。
- 基础CPU/加速器共享内存约定使用无缓存或已有明确可见性机制。驱动按平台要求保证准备数据、启动和读取结果的顺序。

32bit“一周期一拍”只是能力上限。TB应能插入合法等待，模型中若请求不能每周期接受，要报告实际口服务率。

## 5. 固定低比特宏代理

参考OpenC2公开64x64物理位阵列、W4A4实例的数值与接口约束：
- 4096个权重bit，即16个W4逻辑输出列，每列归约K64。
- 64bit行写数据、64行地址。
- 每次输入位平面含64bit，A4按bit3 -> bit2 -> bit1 -> bit0输入。
- 当前输入sign_in固定0；每对权重列的sign_weight分别为0/1。
- 每次返回16个14bit结果；内部已经完成一次原生W4A4操作，外部做W8A8组合。
- 一次只执行一个宏操作，权重编程与计算互斥。计算期间不得改写正在使用的权重与符号配置。
- 一旦start被接受，既定输入采样和结果返回时序不受下游backpressure影响。外围在发射前准备好输入并预约结果存储。

代理独立编写为可综合数字结构。可以使用常量选择、加法树、寄存器和位串行累加；不能用预存最终答案或整个W8A8理想矩阵乘替换低位路径。

公共OpenC2单元库存在空单元体；它不是已经完整验证的FPGA源工程。未经明确许可不直接复制整套RTL发布。所实现的是公开约束启发的数字代理，不宣称真实宏物理等价或FLEX-CIM复现。

### 5.1 在P0固定逐拍时序

使用一个主时钟与clock enable，不用普通逻辑生成新的时钟。
在开始外围流水化前，Codex必须自行给出并验证一张明确时序表，列出：
- start在哪一拍被接受；
- 四个位平面分别在哪一拍采样；
- 结果在哪一拍有效，有效持续多久；
- busy何时撤销、最早何时能接受下个start；
- 权重写入的接受/提交时刻；
- reset如何清理状态与未完成操作。

可优先考察以两个主时钟phase模拟参考正负半拍的方案，最终采用自身仿真确认的时序。公开模板静态推得的约7个宏周期，只作核查线索；不能直接写成7个K7周期。
代理latency、II和任何等效时钟比例都要记录。若为了FPGA时序增加流水级，更新合同、延迟模型和对照条件，不为优化结果单方面放松宏约束。

### 5.2 资源

4096bit容量不意味着单个BRAM能同时提供全部并行权重。按实际数据访问需求采用寄存器/分布式存储/明确分银行，并统计整个代理资源。
外围与代理的资源分项报告，同时保留整个FPGA设计总量。Yosys/Vivado映射结果不代表真实CiM宏工艺面积或能效。

## 6. 调度与缓冲

输出tile t为外层，输入向量p为内层。每tile加载512B权重及8通道参数，驻留处理M个向量。对每个向量依次发射低A4和高A4，合成8输出。tile结束后排空再换权重/参数，第一版不引入跨tile双参数银行。

P1采用阻塞调度贯通完整路径。P2在相同算子、宏合同和数据口条件下增加：
- 双64B输入缓冲；
- 至少两个224bit原生结果包槽，加必要标签；
- 两个输出块上下文，保存各自8个INT32部分和、输出地址、分片状态及最终输出；
- 共享量化流水线；
- 按容量发射的控制。

这里两个上下文是同一任务中的两个8输出块，不是两个任务并发。深度是可工作的起点，不是理论最小值或无气泡保证。

发射规则：
1. 第一轮A4前分配块上下文并预约原生结果槽。
2. 第二轮A4绑定同一块上下文，并另预约本轮返回槽。
3. 每个返回必须携带或准确关联块、tile、分片和输出地址。
4. 原生FIFO弹出后，块部分和仍存活至第二分片合并。
5. 量化已接受的数据也属于在途结果，必须保证落点。
6. 一个块的两个32bit输出写回全部提交后，才释放块上下文。
7. 空间不足时暂停新的start，已启动宏继续完成。

不变量：
occupied_raw_slots + reserved_raw_slots <= raw_depth。
没有ready的内存响应也需要同类预约。任何有限缓存都不能保证在下游无限停顿时持续发射；TB提供有限且合法的等待，并设定合理超时诊断死锁。

重建可采用8组常量移位/加法并行；量化共享1条流水线。若选择串行或复用算术单元，按实际服务次数计算速率。不能把同一共享单元上的重建和量化耗时简单取最大值。

## 7. 控制寄存器、驱动与完成

使用MMIO控制/状态寄存器，不要求新增RISC-V ISA CSR或自定义指令。优先适配现有SoC；未知总线时先提供简单、可测的请求/响应寄存器接口，随后增加薄封装。

建议最小寄存器集合（若已有工程规定，保留语义并记录映射）：
- CONTROL：START、ACK_DONE。
- STATUS：BUSY、sticky DONE、ERROR。
- M、A_BASE、W_BASE、P_BASE、Y_BASE。
- 可选MODE，用于在相同基础资源条件下控制重叠调度。
- TASK_CYCLES，以及少量能解释瓶颈的等待/忙碌计数器。

合法START时锁存完整任务配置；执行中配置写入不得改变当前任务。BUSY期间新START必须有明确的拒绝行为，当前任务继续。
非法M、地址对齐、参数范围等在约定位置拒绝并返回错误，不静默执行错误任务。低成本参数检查可以在驱动/准备工具中完成，并明确硬件检查了什么。

DONE条件：
全部tile/向量完成；宏空闲；原生包预约与占用清零；块上下文、量化、写回均排空；最后写回已提交。
DONE保持到软件清除或下一次合法START；单周期脉冲不足以保证轮询读到。
任务计数器在合法START清零，覆盖权重/参数加载、计算、等待和最终排空。可能重叠的阶段计数不得未经说明直接相加为总周期。

提供裸机C驱动、寄存器定义和小示例。已有RISC-V工程可读时接入；缺失时完成可编译部分和总线级仿真，并将真实CPU执行记为NOT_RUN。不要另起复杂SoC以掩盖缺少接入信息。

## 8. 验证与性能证据

### 8.1 有意义的最小验证

- 数值：符号与极值、U14最高位为1、负权重、bias、量化负数/halfway舍入、饱和。
- 完整路径：M=1和M=125，运行时加载权重/参数，一次启动，最终所有INT8输出逐元素匹配。
- 连续任务：同一RTL/bitstream更换输入、权重和参数，长短任务交替，验证旧状态不会污染下一任务。
- 协议：合法输入响应等待和写回阻塞；不丢、不重、不串块；检查预约容量与最终done。
- 复位：复位后状态确定；按文档约定处理复位时未完成事务，不声称支持暂停恢复。
- 独立参考：直接MAC+官方量化；不只看pre-requant INT32或第一个输出。
- 工具：一种主仿真流程足够，优先现有Verilator/cocotb或可靠的等效流程；只有实际兼容风险才增加第二套工具验证。

参考模型和RTL验证均用固定种子与少量必要边界；不以测试数量作为成果。日志要能指出第一个失配位置、期望值、实际值与对应任务。

### 8.2 真实层数据

先获取固定预训练模型并解析真实权重/bias，使用明确标注的合成激活贯通。
随后在主机端用固定参考运行环境导出目标层真实中间输入，并按锁定reference产生golden输出。真实中间输入的导出不会要求FPGA执行前序层。
保留模型版本、层索引、shape、quant参数、输入来源和导出方法。
当前未要求整网推理准确率；单层正确性不能写成全网准确率已测。

### 8.3 对照和口径

主要对照：阻塞调度与有限缓冲重叠，保持宏时序、数值规则、基本算术资源和数据口合同一致，报告新增缓冲/控制的成本。两种模式可共享代码。
分别报告tile内权重驻留时的稳态和完整任务（包含8次权重tile装载、参数、切换排空和最终写回）。CPU/主机预装数据耗时另列。

M=125时：
- 1000个8输出块，2000次原生W4A4操作。
- 本地输入读取64000B、权重4096B、输出8000B。
- 32bit单共享口最少19024个数据服务拍；若768B参数也走此口，再增加至少192拍。
- 18拍/块是权重已驻留且输入64B+输出8B的端口服务下界。
- 宏约7周期、时钟比r等只可用于条件性分析；最终按已验证代理的latency/II计算。

量化流水线延迟与启动间隔II分开报告。若II为c_q，每8输出块需要约8*c_q的量化服务；同时计入重建带宽与实际共享资源。
优化未获明显收益时如实解释瓶颈，不更改对照条件制造加速。

## 9. 开发阶段与工具缺口

布局布线后检查setup/hold、约束覆盖、关键路径和层次化资源；不能用全局false_path或无约束路径制造通过。
上板结果给出实际任务周期、输出比较、重现步骤及简洁演示。ASIC工具流为主线完成后的可选补充。

每阶段通过后继续下一个当前可执行阶段；只有依赖外部工具/资料/权限的部分暂停。持续更新docs/STATUS.md，避免下一会话重新选题或从零重写。
