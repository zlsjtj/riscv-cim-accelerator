# 共享存储优化 · 50 MHz 输入 scratchpad

本轮对照为公开 `v0.1.0`（原板测位流 `USR_ACCESS=43494d33`）。优化版
保留 K=N=64、运行时 M=1..125、同一 W4A4 宏和量化合同。两个调度模式均使用
scratchpad，原版可用 Git 标签和本地 `build/k7_qpipe/` 复现。

## 从 v0.1 定位瓶颈

用已发布的 RTL 和原固件/SRAM 镜像重跑 SoC，只加入仿真计数器。M1 和 M125
的四个任务计数与对应原板测逐项匹配。M125 的共享口计数为 192 个参数字、1,024 个权重字、
16,000 个输入字、2,000 个输出字。每个 tile 重读 125×64 B；单个任务传入
64,000 B 输入，其中 56,000 B 是跨 tile 的重复读取。

|v0.1 M125 SoC 仿真计数|阻塞|重叠|
|---|---:|---:|
|任务周期|78,172|56,348|
|RUN 周期|74,008|52,184|
|外部读未决拍|17,216|17,216|
|读未决且未在该拍收到响应|0|0|
|共享请求 valid 且 !ready 拍|4|4|
|RUN 中一 / 两个上下文存活拍|73,000 / 0|1,408 / 50,760|
|宏启动次数 / busy 拍|2,000 / 8,000|2,000 / 8,000|
|宏可启动但本拍未启动，且有上下文在等输入|48,000|42,048|
|量化发射 / 落点|8,000 / 8,000|8,000 / 8,000|
|两个上下文同时可发射量化的拍|0|0|
|有块待写 / 其中被外部读阻挡的拍|4,000 / 0|4,000 / 0|

这组条件可重叠，不能加总为任务周期。旧 VCD 的 M125 重叠、tile 0、p=0
片段中，在任务第 593 拍接受输入读并发射量化最后一通道，第 594 拍读响应
到达，第 595 拍见输出就绪，第 596/598 拍提交两个输出字。连续读路径上，
若第 n 拍接受请求，n+1 消费响应，n+2 登记下一个请求，n+3 最早接受它。
K7 实测环境的适配器提供固定下一拍响应。大量空拍来自请求控制的串行化，
重叠模式两个上下文在 RUN 中约 97.3% 的时间同时存活。量化发射和写回
都有固定服务成本，在这组 K7 输入下，共享口就绪背压和量化/写回仲裁等待读
的量级比宏等待输入小。
[原版 RTL](https://github.com/zlsjtj/riscv-cim-accelerator/tree/v0.1.0) ·
本地仿真计数 `build/spad-v01/build/k7/memory_profile.csv`、旧 VCD
`build/repro-v0.1/build/k7_v0.1/quant_overlap.vcd`。

## 两种方案和取舍

|M125 分析推导|A · 外部读调度|B · 输入 scratchpad|
|---|---|---|
|共享口读 / 写字|17,216 / 2,000|3,216 / 2,000|
|共享口输入字|16,000|2,000|
|容量|保留现有两个 64 B 槽，登记或排队少量读元数据|新增 2,048×32 位 = 8 KiB，有效 8,000 B，估计 2×RAMB36|
|端口|同一 32 位共享口，读和输出写竞争|外部口不变，另有本地同步单端口，首 tile 写 2,000 字，后七个 tile 读 14,000 字，可与外部输出写并行|
|控制复杂度|保守实现可在响应沿登记下一请求，将连续读最小接受间隔从 3 降至 2；若要在现有等待合同下支持更密发射，需要在途标签、落点预约及仲裁|以位置和字索引寻址，增加 16 拍读突发计数及一拍返回标签，利用 tile 排空保证填充与重放互斥|
|时序风险|响应判断、偏移更新、写优先和下一请求生成合在同一路径；进一步排队增加 mux 和回压状态|BRAM 地址 mux、返回到输入槽的选择和扇出；同步 BRAM 读切断地址到输入槽的组合链|

选择 B。它在相同外部合同下消除 **14,000** 次共享读，全部共享事务由 19,216
降到 5,216（减少 **72.86%**）。A 的保守实现仍占用原有 19,216 次外部服务，
且会与输出争端口；没有用其最小读间隔推算整任务实测收益。本轮只实现 B。

## 实现与验证

在首 tile 收到每个输入响应时，同一拍填当前输入槽和 scratchpad。后续 tile
仅从 scratchpad 发起 16 字同步读，返回流水带上下文及字索引，完成后才给宏
开放该槽。存储阵列不复位。复位清除突发和返回有效位，新任务先从共享 SRAM
重写该任务会用到的全部地址。两个输出字提交后才释放上下文，最终写提交和
任务排空才置 DONE。驱动已有的任务期间输入不可变约定仍适用。

现有延迟/背压回归增加了本地读写互斥、填充地址唯一、回放地址已写、同步返回
标签/字序、填充与回放总数、以及本地读在途复位后换数据重新提交检查。保留
读响应在途复位、量化在途复位、两种模式、不同 M、连续任务和最终字节比较。
本地 RTL 仿真 16 项、64,512 个字节通过。该测试平台注入外部读返回延迟和
写背压，M125 周期为 59,749（阻塞）/37,721（重叠），M1 两模式均为 7,939。
这些周期只适用于定向等待模型。

同源 SoC 仿真实测，M125 阻塞/重叠为 51,921 / 30,097 拍，M1 两模式均为
4,553 拍。M125 读未决从 17,216 降至 3,216 拍，响应延迟计数仍为 0。宏等输入
从 48,000 / 42,048 降至 21,750 / 15,798 拍。重叠模式双上下文占用从 50,760
降至 24,685 拍。量化仍发射和落点各 8,000 拍，无双上下文发射竞争。待写占 4,000 拍，因未决读
阻挡已就绪写回的计数仍为 0。两个模式的 RUN 周期各少 26,250，另少一拍外部
请求等待。原始计数在 `build/k7_spad/memory_profile.csv`。

同 SoC 的 C 基线使用 xPack GCC 15.2.0 的 RV32IM 标量乘法。内层每读一次
激活就更新 8 个展开的 INT32 累加器，直接使用同一打包权重、bias 和逐通道参数，
并做相同双舍入和两字写回。热函数单独以 `-O3` 编译，反汇编核实八路 `mul`。
软件计时器从内核调用前的 MMIO START 写沿计到 STOP 写沿，包括调用、返回、
全部计算及最后一次 SRAM 提交，输入预装、逐字节比较和 UART 在窗口之外。
与 CiM `CIM_CYCLES` 的结束区别是软件计数还包含最终写后的函数收尾及 STOP。
SoC 定向断言核实两个窗口分别覆盖 16 / 2,000 个输出提交，最终写提交到 STOP
相隔 26 / 29 拍。仿真分别测得 23,010 / 2,749,530 拍，均与 golden 逐字节匹配。

## 同频物理实现

Vivado 2023.2、`xc7k325tffg900-2`、200 MHz 参考输入和 MMCM 50 MHz 主时钟。
两版使用字节相同的 CPU/UART 源、宏、量化器、K7 顶层和 XDC。四段 fixture
（输入、权重、参数、golden）逐字节相同，见 `build/k7_spad/fixture_compare.log`。

|层次 / 指标|v0.1.0|scratchpad|差值|
|---|---:|---:|---:|
|整板 LUT|15,826|16,599|+773|
|整板 FF|10,956|11,015|+59|
|整板 RAMB36|16|18|+2|
|整板 DSP|8|8|0|
|加速器 LUT|10,735|10,633|−102|
|加速器 FF|7,974|8,000|+26|
|加速器 RAMB36|0|2|+2|
|加速器 DSP|4|4|0|
|WNS / WHS (ns)|+5.885 / +0.038|+6.329 / +0.062|+0.444 / +0.024|

候选 scratchpad 使用两个 RAMB36E1。Vivado 物理映射分别使用写端口和读端口，
RTL 仍按 tile 分时，控制器只会访问一种操作。整板 LUT 差额包含新版固件 ROM
及软件计时器，CPU 层级报告由 5,053 增为 5,925 LUT。加速器层级与整板应分别
对照，整板差值不能作为 scratchpad 独占面积。

候选布通 28,947 / 28,947 条可布线网。TNS/THS、内部未约束端点、无时钟端点及
DRC 错误为 0，保留 20 条 DSP 流水建议，`REQP-1839` 为 0，异步 UART TX
为唯一输出例外。最差 setup 为量化乘积寄存器到 `output_bytes_reg[0][1]`，
数据路径 13.423 ns，其中路由 6.962 ns。两版均通过 50 MHz，裕量差值来自
本次物理实现。报告来自 `build/k7_qpipe/` 和 `build/k7_spad/` 的
`utilization.rpt`、`timing.rpt`、`check_timing.rpt`、`drc.rpt` 与 `critical_paths.rpt`。
候选 routed DCP 的 scratchpad 定向 setup 报告显示，BRAM 读出到输入槽的最差
路径为 5.685 ns、裕量 +14.163 ns，写入端为 6.180 ns、裕量 +13.322 ns。
见 `build/k7_spad/spad_read_path.rpt` 和 `spad_write_path.rpt`。

## 50 MHz 实板对照

2026-11-05 在同一 K7 重载 v0.1.0 `43494d33`，复现原四项结果和两次热复位，
随后加载候选 `43494d34`。同一真实 tensor23、权重、参数及 golden，统一按 20 ns
换算。CiM 窗口由 START 覆盖到最后一个 SRAM 提交和 DONE，包含首 tile 的
scratchpad 填充，CPU 预装、输出比较和 UART 不在窗口内。

|M|模式|v0.1.0 周期 / µs|scratchpad 周期 / µs|任务时间减少|
|---|---|---:|---:|---:|
|1|阻塞、重叠各一项|4,764 / 95.28|4,553 / 91.06|4.43%|
|125|阻塞|78,172 / 1,563.44|51,921 / 1,038.42|33.58%|
|125|重叠|56,348 / 1,126.96|30,097 / 601.94|46.59%|

四项候选任务逐字节比较 16,128 个 INT8，全部匹配。M1 每项提交 16 字，M125
每项提交 2,000 字。两种模式均在 BUSY 时热复位，捕获旧读响应且保留原已
提交的 2 字，任务状态及计数归零后重新提交成功。硬件周期及复位快照与 SoC
仿真一致。本地 scratchpad 读在途复位覆盖来自独立 RTL 回归。

|同 SoC 软件|SoC 仿真周期|K7 板上周期 / µs|K7 输出比较|
|---|---:|---:|---:|
|RV32IM C，M1|23,010|23,013 / 460.26|64 / 64|
|RV32IM C，M125|2,749,530|2,749,533 / 54,990.66|8,000 / 8,000|

软件计时板测比仿真各多 3 拍，表中分别列原始计数。M125 的 C 对重叠候选在
各自上述窗口内为 91.36×，这个比值对应本板的标量 CPU、当前固件和算子窗口。
JTAG 核对了两个版本的 USR_ACCESS。原位流摘要仍为
`b2c18a796ce1559535d6723b9dbb4ac84b02f081a6ff34215457367bc6c67805`，候选位流为
`6edd75535092b9cd1a174415b1ef02a6cb6332e92ff9b381d0275e25af3ba81b`。
原版重测 UART 在 `build/spad-v01/build/board_recheck/board_uart.log`，候选 UART、
结果 JSON、核对记录及逐工况 CSV 在 `build/k7_spad/` 的 `board_uart.log`、
`board_results.json`、`verification.log` 和 `board_comparison.csv`。

## 复现入口

```powershell
python tools/run.py --model --simulator questa
python tools/k7.py prepare --cpu-source $cpuSrc --gcc-bin $rvBin
python tools/k7.py sim --cpu-source $cpuSrc --trace-blocks
python tools/k7.py impl --cpu-source $cpuSrc
python tools/k7.py program --jtag $jtagSerial --port $serialPort
```

首次未生成激活时按 README 安装依赖，并改用 `--real-activations`。
工具记录到 `build/k7_spad/`。`sim --trace-blocks` 另外写出每任务
`memory_profile.csv`。原版在独立的 `v0.1.0` checkout 中，用该版 `prepare`
生成同源镜像，或使用与旧源匹配的 `build/repro-v0.1/build/k7_v0.1/` 镜像和
`build_metadata.json`、`cpu_include/` 副本。将本轮 `tb/tb_rv_system.sv`
复制到独立 checkout，运行该版 `k7.py sim --trace-blocks`，使用原版工具的
编译设置即可关闭仅候选版存在的软件计时断言。本轮原版仿真位于 `build/spad-v01/`。
完整整板需要有权使用的外部 JYDD CPU/UART。原始与本轮位流及测试数据均留在本地。
