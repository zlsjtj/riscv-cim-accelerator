# 五分钟设计讲解

**0:00–0:45 · 任务与接口**

两层固定 K=N=64，M 运行时可选。CPU 用 `sw/cim.c` 写两套权重和
参数地址，提交一次 START。CiM 的状态机负责两层，CPU 等 DONE 后
从共享 SRAM 读取最终输出。公开的 Ibex 示例实际执行这段固件，并
检查中间和最终两层。

**0:45–1:45 · INT8 如何通过低位宏**

`rtl/cim_macro.sv` 是可综合的数字宏代理。每个 INT8 权重分为
无符号低 nibble 与有符号高 nibble。激活先转换为 `q + 128`，
再用两个无符号 nibble 输入，每次以 4 个位平面送宏。外围在
`rtl/cim_accel.sv` 按位权重重建 INT32，加入 bias，再交给
`rtl/requant.sv` 做定点乘法、双舍入、零点与饱和。独立 golden
直接做宽整数 MAC，逐字节比较两级 INT8。

**1:45–2:45 · 结果与上下文如何保持正确**

宏一旦启动就会返回结果，调度器必须提前预约原生结果槽。两个上下文
各自保存行号、部分和和写回状态。SRAM 背压期间，已登记请求保持
地址与数据。高字实际提交后旧行才能释放，整个任务在最后一笔提交
并排空后置 DONE。定向仿真分别阻塞低字和末字，检查所有权并在阻塞
时复位。

**2:45–4:00 · 优化来自哪里**

第一层写共享 SRAM 时同步保留中间激活，M125 省去 2,000 个 SRAM
读字。第二层最后一个高 nibble 位平面送入宏后，旧行的输入槽可以
提前装下一行。最后再把低字写回和高字量化重叠。指着首个 tile
波形讲一组数字。原方案第 33 拍提交低字、第 35 拍提交高字、下一
行第 37 拍发宏。最终方案改为第 29 拍、第 33 拍和第 34 拍。
[逐拍记录](INTERLAYER_WRITEBACK.md)

**4:00–5:00 · 给出同一口径的结果并演示**

同一 K7 50 MHz 位流，M125 两次 START 为 943.94 µs，最终链式为
794.60 µs，降低 15.82%。提前写回这一步贡献 30.02 µs。展示
`python3 tools/run_ibex.py` 的 `CIM_PASS`、两个 INT8 文件、
`result.json` 与 CPU 指令轨迹。这里的开放整机是 RTL 仿真，
K7 性能来自原始实板 UART，两份结果各有自己的计时窗口。
